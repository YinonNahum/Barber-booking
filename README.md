# ינון נחום · אתר קביעת תורים

אתר סטטי (HTML/CSS/JS ללא ספריות) עם Supabase כמסד נתונים, מתארח ב-Netlify.

## עמודים
| עמוד | למי | מה |
|---|---|---|
| `index.html` | לקוחות | עבודות, שירותים, קביעת תור, רשימת המתנה |
| `manage.html?t=…` | לקוחות | צפייה וביטול תור דרך קישור אישי |
| `admin.html` | הספר | יומן, שעות, שירותים, לקוחות וחובות, המתנה, צפיות, הודעות, הגדרות |

## כללים עסקיים (נאכפים במסד הנתונים)
- לקוח רואה רק שעות פנויות. שני תורים לא יכולים לחפוף (אילוץ `bookings_no_overlap`).
- ביטול חינם עד X שעות לפני (ברירת מחדל 3, ניתן לשינוי בהגדרות). ביטול מאוחר מחייב אישור ונרשם חוב במחיר מלא.
- ביטול תור מסמן את הממתינים לאותו יום כ"התפנה מקום".
- כל תור יוצר הודעת אישור + תזכורת ל-08:00 בבוקר התור בטבלת `notifications` (סטטוס `pending`).
- החשבון הראשון שנרשם ב-`admin.html` הופך למנהל היחיד.

## מבנה
- `js/config.js` – כתובת Supabase ומפתח ציבורי (בטוח לפרסום).
- `js/api.js` – לקוח REST/RPC/Auth מינימלי, פורמט תאריכים, רישום צפיות.
- `js/booking.js` – זרימת קביעת התור.
- `js/admin.js` – אזור הניהול.
- `supabase/migrations/` – כל הסכמה, ההרשאות והפונקציות.
- `tests/` – בדיקות ממשק אופליין עם Playwright (`node tests/shoot-site.js /tmp`).

## שלב 2: שליחת הודעות
ההודעות נשמרות בטבלת `notifications`. כדי לשלוח אוטומטית:
1. לבחור ספק SMS או WhatsApp (למשל ספק SMS ישראלי, Twilio, או WhatsApp Business API).
2. ליצור Supabase Edge Function שרצה כל 5 דקות (Cron), שולפת `status='pending' and scheduled_for <= now()`, שולחת, ומעדכנת `status` ל-`sent`/`failed`.
3. לשמור את מפתח הספק כ-secret של ה-Edge Function, לא בקוד.

עד אז, בעמוד "הודעות" בניהול אפשר לשלוח כל הודעה ידנית בוואטסאפ בלחיצה.
